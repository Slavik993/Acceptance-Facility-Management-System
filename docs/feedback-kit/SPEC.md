# Кнопка замечаний о платформе: перенос из ProDisser в «Приёмку»

Техническое задание к `PROMPT.md`. Источник механизма — сайт и кабинет
ProDisser (репозиторий `klemmerpavel-beep/Scientific-Consulting-Service_Web`,
коммит `f702268`, решения Р-403, Р-405, Р-583). Цель — «Приёмка» для DOLGIY
STUDIO (`klemmerpavel-beep/Acceptance-Facility-Management-System`).

## 1. Как это устроено в ProDisser

### 1.1. Поток замечания

```
кнопка в углу экрана ──► POST /api/feedback ──► таблица Feedback (PostgreSQL)
  (все страницы сайта        проверки сервера:        │
   и все экраны кабинета)    текст, контакты,         ├─► экран «Замечания» (руководитель):
                             шаблон адреса,           │     плитки, отбор, разбор, «Выгрузить .xlsx»
                             снимок по сигнатуре,     ├─► «Замечания.xlsx» на Яндекс Диске (раз в час)
                             критичность правилами    └─► выгрузка по ключу для исполнителя правок
                                                            (Claude Code): перечень, снимки, разбор
```

Еженедельный цикл: замечания копятся неделю. В субботний выпуск
исполнитель забирает открытые (`feedback-pull.mjs --open`) и правит их по
порядку критичности. Каждое отработанное замечание он отмечает «исправлено»
с записью «что сделано» и номером решения. За 04—13.10.2026 так отработано
тридцать замечаний владельца (Р-583).

### 1.3. Принципы, которые переносятся без изменений

1. Сервер клиенту не верит: шаблон адреса, устройство и критичность
   считаются на сервере тем же модулем, которым экран показывает человеку
   «что уйдёт».
2. Замечание описывает экран, а не человека. Текст с телефоном, почтой или
   ссылкой на мессенджер не принимается.
3. Таблица всегда полная: книга собирается целиком при каждой выгрузке.
4. Критичность по правилам только ставит замечание в очередь. Итоговую
   ставит руководитель.
5. Исполнитель правок работает по отдельному ключу, который открывает
   только замечания. Учётной записи в продукте у него нет.
6. Отказ называется словами. Сбой записи — 503 с просьбой повторить.

## 3. Что делается

Два контура, одна кнопка.

- **Продукт (основной).** Кнопка «Замечание» на всех экранах кабинета у
  всех четырёх ролей. Запись идёт в собственную базу. Руководитель
  разбирает замечания на экране «Замечания» и выгружает книгу Excel.
  Исполнитель правок забирает замечания по ключу.
- **Демонстрация.** Та же кнопка и та же форма; транспорт — прежний
  приёмник Apps Script через двойник API. Без `VITE_FEEDBACK_URL` кнопки
  нет, как сейчас. Прежний `Feedback.tsx` заменяется общей кнопкой.

Каждое можно сменить одной строкой в промпте.

## 4. Модель данных

Миграция `apps/api/prisma/migrations/<дата>_feedback/migration.sql`:

```prisma
enum FeedbackKind { DEFECT IDEA COMMENT WORKS }
enum FeedbackSeverity { CRITICAL HIGH MEDIUM LOW }
enum FeedbackStatus { NEW IN_WORK DONE DECLINED }

/// Замечание о платформе с кнопки в кабинете (перенос Р-403 ProDisser).
/// Автор — ролью, без имени: замечание описывает экран, а не человека.
model Feedback {
  id        String   @id @default(uuid()) @db.Uuid
  orgId     String   @db.Uuid
  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt

  kind          FeedbackKind
  authorRole    Role
  routeTemplate String          /// `#[объект]/estimate`
  section       String          /// подпись раздела
  objectCode    String?         /// `R-99`, только видимый автору объект организации
  tab           String
  text          String          @db.Text
  device        String
  viewportWidth Int?

  screenshotKey  String?        /// `feedback/<uuid>.<ext>` в FileStorage
  screenshotType String?
  screenshotSize Int?

  severityAuto FeedbackSeverity
  severity     FeedbackSeverity
  status       FeedbackStatus   @default(NEW)
  note         String?          @db.Text
  resolvedAt   DateTime?

  organization Organization @relation(fields: [orgId], references: [id], onDelete: Cascade)

  @@index([orgId, status, createdAt])
  @@index([orgId, createdAt])
  @@map("feedback")
}
```

Стиль имён и `@@map` сверить с соседними моделями схемы. CI-работа «Схема
совпадает с миграциями» обязана остаться зелёной.

## 7. Сервер (`apps/api/src/feedback/`)

`FeedbackController`, `FeedbackService` и `FeedbackExportController`;
провайдеры — в `app.module.ts`. Внешний адрес — `/api/…`: nginx снимает
приставку.

| Маршрут | Доступ | Что делает |
|---|---|---|
| `POST /feedback` | `@Roles("OWNER","FOREMAN","ACCOUNTANT","CLIENT")` | Разбор `prepareFeedback`. Роль и `orgId` — из сессии. `objectCode` сохраняется, только если объект есть в организации и виден этой роли (`project-scope`), иначе `null`. Снимок: сигнатура (`detectImageType`) → `безМетаданных` → `FileStorage.put("feedback/<uuid>.<ext>")` → строка; при сбое строки файл убирается. Предел — 20 замечаний на пользователя за 10 минут (в памяти). Ответ `{ ok: true }` или 400/413/429 с текстом |
| `GET /feedback?status&severity&kind&page` | `@Roles("OWNER")` | Перечень организации, свежие сверху, по 50 |
| `GET /feedback/digest` | `@Roles("OWNER")` | Плитки |
| `PATCH /feedback/:id` | `@Roles("OWNER")` | Разбор. `resolvedAt` ставится при переходе в `DONE`/`DECLINED`, сохраняется при переходе между ними и снимается при возврате. Журнал — `AuditService.record` клиентом той же транзакции; поля `status`, `severity`, у `note` — признак «заполнено», без текста |
| `GET /feedback/book` | `@Roles("OWNER")` | `buildFeedbackBook` по организации, `attachment; filename*=UTF-8''Замечания …xlsx` |
| `GET /feedback/:id/screenshot` | `@Roles("OWNER")` | `inline`, тип из базы, `x-content-type-options: nosniff` |
| `GET /feedback/export[?status=NEW,IN_WORK]` | ключ | Перечень с подписями: `kindLabel`, `severityLabel`, `statusLabel`, `roleLabel`, `createdAtLocal`, `resolvedAtLocal`, `screenshot: {type,size}`/`null`; до 5000 строк |
| `GET /feedback/export/book` | ключ | Та же книга |
| `GET /feedback/export/:id/screenshot` | ключ | Снимок |
| `PATCH /feedback/export/:id` | ключ | Разбор, как у руководителя; `actorId = null` |

**Вход по ключу** (перенос `feedback-export.ts`):

- `Authorization: Bearer <ключ>`;
- `FEEDBACK_EXPORT_TOKEN` от 32 знаков;
- организация — `FEEDBACK_EXPORT_ORG` (её `id`);
- без любой из двух переменных, при неверном ключе или чужой организации —
  404 «Не найдено»;
- сравнение `timingSafeEqual` отпечатков SHA-256;
- 300 запросов за 10 минут на адрес (`x-forwarded-for`, последний узел);
- `cache-control: private, no-store`, `x-robots-tag: noindex`.

Маршруты ключа идут мимо `SessionGuard`; соседний страж сессии их не
перехватывает.

**nginx.** В `apps/web/nginx.conf` нет `client_max_body_size`, а умолчание
nginx — 1 МБ. Снимок больше 1 МБ получит 413 от nginx раньше сервера; то же
касается снимков приёмки и сметы до 10 МБ. Предел задаётся явно:
`client_max_body_size 11m;` в `location /api/`. Довод — в комментарии рядом.

## 9. Еженедельный цикл

1. Неделю замечания копятся. Срочное — авария, потеря данных, неверные
   деньги — разбирается в тот же день.
2. В день выпуска исполнитель выполняет
   `node scripts/feedback-pull.mjs --open`. Замечания группируются по
   экрану (`routeTemplate`) и правятся по порядку: критично → низкая.
3. Взятое в работу отмечается `review <id> status=IN_WORK`. Сделанное —
   `status=DONE note="что сделано; решение/PR"`. Отклонённое —
   `status=DECLINED note="почему"`.
4. «Работает верно» читается до правки экрана. Закрывается `DONE` с
   пометкой «учтено при правке …».
5. Руководитель видит то же на экране «Замечания» и в книге Excel.

`13_FULL_AUDIT.md`.

## 11. Критерии приёмки

- [ ] Кнопка есть на каждом экране у каждой роли и не закрывает данных на
      390 и 1440 px.
- [ ] Замечание ложится в базу за одно действие с видом, экраном,
      объектом, вкладкой, устройством и критичностью.
- [ ] Текст с телефоном или почтой не принимается; отказ назван словами.
- [ ] Руководитель видит замечания своей организации, разбирает их и
      выгружает книгу Excel с листами «Замечания» и «Сводка».
- [ ] Прораб и заказчик чужих замечаний не видят (403).
- [ ] Исполнитель по ключу получает перечень, снимки и книгу и отмечает
      разбор; без ключа — 404.
- [ ] Демонстрация пишет в Google-таблицу как прежде, без поля имени.
- [ ] `pnpm lint`, `pnpm typecheck`, `pnpm test`, работы «Быстрая» и
      «Стенд» — зелёные.
- [ ] Решение записано: `01_PROJECT.md` (объём), `06_PLAN.md` (пункты и
      состояние), `12_FEEDBACK.md` (два контура), `10_QUIZ.md` или
      `13_FULL_AUDIT.md` (решение заказчика с датой — по принятому в
      проекте порядку).

## 12. Настройка ключа исполнителя (один раз, после выката)

```bash
# на сервере, в каталоге поставки
echo "FEEDBACK_EXPORT_TOKEN=$(openssl rand -hex 32)" >> .env
echo "FEEDBACK_EXPORT_ORG=<id организации DOLGIY STUDIO>" >> .env
docker compose up -d api
```

В облачной среде Claude Code:

- меню среды → Edit → переменные `FEEDBACK_EXPORT_TOKEN` (та же строка) и
  `FEEDBACK_EXPORT_URL` (адрес стенда);
- Network access → Custom → домен стенда.

Значения подхватывает новый сеанс. В `docker-compose.yml` обе переменные
пробрасываются службе `api` пустыми по умолчанию:
`${FEEDBACK_EXPORT_TOKEN:-}`.
