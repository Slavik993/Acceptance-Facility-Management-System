# Кнопка замечаний о платформе в кабинете «Приёмки»

Скопируйте всё ниже черты первым сообщением в новый сеанс Claude Code на
репозитории `klemmerpavel-beep/Acceptance-Facility-Management-System`.
Перед этим положите папку `feedback-kit` в `docs/feedback-kit/` репозитория
или приложите архив `feedback-kit.zip` к сообщению.

---

**Задача.** Встроить в кабинет «Приёмки» кнопку замечаний о платформе с
автоматическим сбором в таблицу и выгрузкой в Excel. Механизм уже работает
на сайте и в кабинете ProDisser (решения Р-403, Р-405, Р-583 его журнала).

Любой вошедший — руководитель, прораб, бухгалтер, заказчик — нажимает
кнопку в углу экрана и отмечает:

- **ошибку** — что работает неверно;
- **рекомендацию** — что улучшить;
- **комментарий** — вопрос или мысль;
- **«работает верно»** — место, которое при доработке трогать нельзя.

Замечание записывается вместе с обстановкой: раздел, объект, вкладка,
адрес экрана, устройство, ширина окна, необязательный снимок. Критичность
выставляется правилами при отправке. Руководитель разбирает замечания на
экране «Замечания» и выгружает книгу Excel. Исполнитель правок (Claude
Code) забирает их по отдельному ключу и отмечает, что сделано.

**Основание.** Решение владельца продукта от 24.10.2026. Оно расширяет объём
и отменяет строку `12_FEEDBACK.md` «В продукте его нет». Первым коммитом
запиши решение в документы проекта по принятому порядку:

- `01_PROJECT.md` — объём;
- `06_PLAN.md` — пункты и состояние;
- `12_FEEDBACK.md` — два контура, продукт и демонстрация;
- реестр решений заказчика — `10_QUIZ.md` или `13_FULL_AUDIT.md`.

**Материалы — `docs/feedback-kit/` или приложенный архив:**

- `SPEC.md` — техническое задание: модель, маршруты, экраны, книга,
  вход по ключу, стражи, критерии приёмки. Прочитать целиком до начала
  работы.
- `templates/` — проверенные заготовки:
  - правила замечаний (`packages/domain`), 23 теста;
  - книга Excel (`packages/importer`, exceljs), 6 тестов;
  - утилита `scripts/feedback-pull.mjs`.
  
  Перенести как есть. Править только при расхождении с текущим
  репозиторием, и с объяснением в описании запроса на слияние.
- `reference/prodisser/` — исходники механизма ProDisser (Next.js) для
  сверки устройства. Переносится устройство, а не код: стек здесь —
  NestJS/Fastify, Prisma, Vite/React.

**Порядок работы — ветка `claude/…`, осмысленные коммиты:**

1. Документы: решение, объём, план.
2. Домен и книга из заготовок; контракты zod в `packages/contracts`.
3. Модель `Feedback` и миграция (SPEC §4).
4. Сервер `apps/api/src/feedback/` (SPEC §7):
   - приём у четырёх ролей; разбор, книга и снимок — уровню руководителя;
   - вход по ключу `FEEDBACK_EXPORT_TOKEN` и `FEEDBACK_EXPORT_ORG`;
   - `client_max_body_size` в `apps/web/nginx.conf`.
5. Клиент (SPEC §8):
   - кнопка в оболочке у всех ролей и экран «Замечания» в «Ещё»;
   - в демонстрации та же кнопка через двойник API в приёмник Apps
     Script; поле имени снято; прежний `Feedback.tsx` заменён.
6. Стражи (SPEC §10): тесты сервера, `verify-api`, `verify-page`,
   `verify-demo`. Каждый новый страж проверяется откатом, число
   замечаний — в описании запроса на слияние.
7. `feedback-export/` — в `.gitignore`; настройка ключа (SPEC §12) — в
   документации поставки.

**Решения по умолчанию** (SPEC §3.1, Д-1…Д-7):

- кнопка у всех четырёх ролей;
- четыре вида замечаний;
- автор хранится ролью, без имени;
- снимок разрешён, EXIF снимается, снимок видит только уровень
  руководителя;
- разбор — `@Roles("OWNER")`;
- в продукте никаких внешних служб;
- поле «Кто пишет» в демонстрации снимается.

**Правила проекта действуют полностью:**

- работа на `main` запрещена;
- запрос на слияние — по шаблону проекта, вливание — только по согласию
  владельца;
- новых зависимостей нет: `exceljs` уже есть в `@priyomka/importer`,
  `sharp` — в `@priyomka/api`;
- денежные пути не трогаются;
- цвета, размеры и отступы — только токены `packages/ui`; тон текстов —
  по `03_DESIGN_SYSTEM.md`;
- журнал — клиентом транзакции (БП-10);
- каждый запрос знает `orgId`.

Противоречие с `01_PROJECT.md` — остановиться и спросить. Во всём
остальном действовать по SPEC без вопросов.

- что ждёт владельца: выкат, ключ исполнителя (SPEC §12), переменная
